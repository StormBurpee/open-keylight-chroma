# Native SPI transport recovery tests

Run `python tests/transport/run_tests.py` with an AddressSanitizer-capable Clang in PATH (or `CC`). The tests compile the actual `firmware/main/nxp_transport.c` and `okl_nxp.c`; they replace only ESP-IDF hardware/RTOS boundaries. The runner records tested source digests and results under `build/transport-tests/`.

The regression starts from an ordinary driver request receiving a two-byte zero length. That remains a failed getter, but recovery waits for READY high without inventing a body read. It preserves the consumed-length boundary across timeout, then admits a subsequent correlated getter. Startup stale replies, delayed stock replies, malformed lengths, mutex/deadline failures and SPI errors are also exercised.

The mock enforces the installed [ESP-IDF 5.5.5 polling contract](https://github.com/espressif/esp-idf/blob/b774170ff46c393eeb5e495ea37936038d3f4f4f/components/esp_driver_spi/src/gpspi/spi_master.c#L1424): start requires `portMAX_DELAY`. Start errors occur before wire setup, whereas end can report a DMA error after completing the transfer. Tests distinguish those paths in request, length and body phases. An end error leaves an unknown protocol phase; even an explicit recovery must refuse further clocks at either READY level. This is a fault requiring lifecycle recovery, not a successful automatic repair.

The one-device SPI host is protected by the application's deadline-bounded mutex. Polling start/end use the API's supported infinite wait so DMA cannot outlive their stack buffers; the absolute deadline is checked before and after. Wire duration is not a hard scheduling or hardware-hang bound. Another uncoordinated user of this SPI host would invalidate the exclusive-host assumption.

An original controller may expire an unconsumed reply after 100 ms. If the ESP last recorded a sent request and currently sees READY high, the transport cannot distinguish that expiry from a stock response still being prepared. Tests require bounded failure and retained recovery poison in this case. A future explicit peer/lifecycle contract is needed before changing it; elapsed time and a high pin alone are not evidence of a known idle peer.

Updater tests use the same actual transport and portable loader report validator. A logical job lease, exact loader-information qualification and a fully completed End/Abort send are required to arm an expected-reset boundary. Wrong leases, opcodes, unknown DMA outcomes, incomplete sends, short quiet intervals and READY-low cannot clear it. A valid boundary is one-shot and requires at least three seconds of silence. Ordinary recovery cannot clear a pending reset. Legacy entry is a single fixed mode1 send with no speculative ACK clocks; original entry consumes and validates its exact ACK before arming the separate entry boundary.

The resident loader uses a zero routing tag with response kind0, unlike an application reply that echoes its caller's tag. Tests use that resident envelope for loader qualification and exhaust all 256 kinds with zero, own and foreign tags. Only the typed loader path admits zero-tag/kind0; application getters and original entry acknowledgements keep their identity checks. An envelope alone cannot qualify a loader: its complete information signature is still required.

A read-only diagnostic snapshot records the last fully consumed response body, including invalid envelopes or reports, without clocking SPI or clearing an uncertain phase. It labels these as raw bytes; DMA-error buffers are not marked complete. The next request attempt clears the cache. Tests cover complete bodies that exceed their deadline, malformed replies, denied locks and uncertain DMA outcomes.

These host tests do not qualify physical pin timing, repair ambiguous SPI/DMA failure phases, or establish the peer's pending length/body boundary after an ESP reset. Recovery assumes a startup READY-low response is awaiting its length, as the pre-existing implementation does. A consumed nonzero length can also become stale if the original peer expires before its body is drained; that broader recovery boundary remains unqualified. No flash, reset, GPIO writes or device requests are performed by the tests.
