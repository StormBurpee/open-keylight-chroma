# Bounded NXP application update core

This component accepts a versioned package containing one complete original 28 KiB application bank. Its API exposes no arbitrary address, partial write, bootloader replacement, vendor restore, or automatic retry operation. The fixed logical interval is `0x2000..0x8fff`; the retained controller loader maps this interval to staging.

Create a package with `python tools/package_controller.py original-bank.bin controller.oklnxp --version 0.1.0.0` from the repository root. The tool requires an exact complete bank and explicit version, validates its vector bounds, refuses existing output by default, and prints both package and bank SHA-256 values. It never uploads. Use the package digest for the HTTP `X-SHA256` header; the bank digest is embedded in the package.

`okl_loader_prepare` validates the container, target part, ABI, declared lighting role, vector table and SHA-256 before any controller I/O. The package must stay immutable through `okl_loader_run`, which repeats validation. Metadata and a digest do not authenticate a publisher, prove original source or qualify hardware. An authenticated owner may install their own build and is responsible for its source and hardware qualification; there is no central hash allowlist. This component does not supply an HTTP endpoint or an authentication policy.

The worker grants one logical exclusive lease. All other controller jobs, including output-off and health polls, are rejected or paused until the updater releases it. This lease is distinct from the physical SPI mutex used by each exchange. Before entry the adapter verifies a dark, owned supported original controller, the separately reviewed legacy 1.3 migration source, or a positively identified fresh resident loader. A timeout never identifies a source. A resident loader with unknown pending program state is not a fresh loader: preliminary reads could flush its RAM buffer, and Start does not clear that pending buffer. The fresh-resident source is internal adapter evidence, never a user-selectable bypass.

Abort is a reset, not a command that forces the loader to remain running. With a valid active application after a precommit failure it normally returns that application; a separate typed entry can then establish a fresh loader. An ambiguous SPI phase must not be cleared merely to send Abort. An attempted commit is outside this precommit recovery path.

The core verifies the exact resident information response, erases the entire staging interval, accepts 448 exact program acknowledgements, and reads all 448 blocks back. The first read also flushes the final buffered sector. Only byte-for-byte verification plus the pinned digest permits one commit attempt. Intent is persisted before entry, erase, programming and commit. Persisted state is evidence on restart, never a queued operation to replay.

After an End attempt the same lease remains held with **no SPI traffic for at least three seconds**, even on transport error or cancellation. The adapter must then establish an explicit expected reset boundary. A complete known no-reply command and an ambiguous DMA outcome are different states; READY-high alone cannot clear an unknown transfer. Without boundary evidence, the result remains unresolved and observation is not attempted.

Post-commit classification uses read-only probes. A matching original ABI/part/version, lighting role and capabilities, with fresh dark state, can return `OKL_LOADER_OK`; confirmation is still a separate worker lifecycle decision. The updater does not send FD or replay old output. A known resident loader is reported but not automatically flashed again. Precommit failures attempt at most one Abort after positive loader identification; postcommit failures never Abort, retry End or restore another image.

The transport adapter must finish outstanding DMA before returning and must report whether sending completed or may have happened. Application deadlines cannot make a hardware hang cancellable. The monotonic wait callback must keep advancing real time; a broken clock cannot support a quiet-period guarantee. These are explicit adapter obligations, not properties established by host tests.
