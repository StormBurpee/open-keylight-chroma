# Open Keylight Chroma 0.2.0-alpha.1

The first guided-installer candidate: original applications for both controllers, a dashboard served by the light, and a local setup experience built with React and Ink.

**Draft qualification record. This candidate has not completed its live installation and upgrade checks and is not yet published as an installation release.**

## Install

Download the Windows x64 setup ZIP, extract it completely, then open `start-open-keylight.cmd`. It prepares verified portable runtimes, finds your light and downloads the reviewed stock recovery image directly from Razer. Stay beside the light for the dark and five-colour checks.

Read [Getting started](../getting-started.md) before installation. The supported stock starting profile is ESP **1.0.13.0**, NXP **1.3.0.0**, with the exact reviewed resident loader and controller identity. Other variants are rejected or remain unqualified.

## Component versions

- ESP application and embedded dashboard: **0.2.0-alpha.1**.
- NXP lighting application: **0.1.1.0**, plus the installer's separate identity, dark and low-output diagnostics.
- Guided installer: **0.2.0-alpha.1**.
- Companion Stream Deck plugin (separate package): **0.1.3**, requiring Stream Deck 7.0 or newer.

The setup ZIP includes `SHA256SUMS` for its payloads. `release.json` identifies the source commit, ESP ELF and installer bundle. No proprietary firmware, device tokens or private captures are distributed.

## Verified so far

- Both original applications run on the first reference light; its dashboard, native updates, saved configuration and bounded lighting tests have passed.
- On the second light, all four controller transfers and readbacks passed. Its owner observed complete darkness and all five correct low pulses. A later recovery run completed ESP acceptance with exact image/assets, low-white/Off checks and explicit confirmation. That recovery used a private pinned adapter; the public TUI's uninterrupted live migration remains unqualified.
- The fixed reader passes real HTTP connection tests, including fragmented, compressed and truncated responses.
- The guided interface passes real Python-process integration, observation prompts and acceptance handoff tests on Windows and Linux. These tests use modeled device transport, not a live lamp.
- Portable Windows runtimes, isolated Python imports, private credential storage, archive extraction limits and reproducible packaging have been exercised.

## Known limits

This is early-access firmware for reviewed hardware, not general board qualification. Long-duration electrical and thermal measurements remain open. The retained ESP bootloader does not automatically recover an early crash; application fallback only works if the trial application can run. Some controller failures require a physical power cycle.

Use the dashboard on a trusted local network. HTTP tokens authenticate requests without encrypting them. Native updates preserve the bootloaders and partition layout; never substitute a merged flash image or use `idf.py flash` on an existing light.

Detailed observations and failed attempts are recorded in [PROGRESS](../../PROGRESS.md).
