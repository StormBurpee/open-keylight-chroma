# Colour rendering

Desired RGB is the selected hex colour. The default `srgb` setting converts those display channel values to linear output through a rounded 256-entry sRGB lookup table; `linear` sends linear channel values. Brightness scales the converted channels once. White brightness and temperature use their existing native controls.

The colour renderer holds the controller's RGB master at 255. It seeds the custom framebuffer before selecting custom mode, so an established Static colour at that master does not need to be muted during the handoff. Retargeting an active stream reuses its last acknowledged frame only after checking the current owner identity and name. An unknown external custom framebuffer has no getter, so takeover starts conservatively from a muted black frame. Importing a legacy Static colour at a lower native master also requires a non-atomic conversion to the canonical master; that first handoff can briefly dim.

Both instant and smooth changes use this frame path. A zero-duration change sends the target frame immediately after setup. A smooth change samples elapsed time, starts from the observed or last acknowledged output and does not replay delayed samples. Its final sample must actually reach the duration before completion; a slow acknowledgement alone cannot turn an earlier sample into an endpoint.

At completion, the worker sends native Static with the exact last acknowledged raw RGB while keeping the master unchanged. The legacy custom-to-Static transition therefore has zero intended colour delta. Fresh getters must then match raw RGB, master 255, Static mode and white brightness zero before the chosen RGB and percentage are reported as confirmed. A readback mismatch or failed exchange is an error, not an automatic retry. This establishes controller-state agreement, not optical measurement.

The native controller does not retain the separate chosen RGB, encoding and percentage. Within the running ESP application, that intent remains associated with its exact matching raw tuple, including restoration after a failed upload indicator. An ESP restart loses that association. Bootstrap therefore adopts a nearest sRGB display estimate (or the raw channels in linear mode), and a percentage derived from the native master. For a previously canonical colour, that percentage is 100. These reconstructed RGB and brightness fields are **unconfirmed** until a new requested intent passes forward readback. This prevents applying sRGB conversion twice on a brightness-only change, but does not recover the original chosen hex or percentage. No saved scene or NVS record is rewritten during adoption.

The controller frame has eight bits per channel. sRGB conversion and low brightness leave fewer distinct nonzero output levels, so very dim fades can still show steps. Host tests establish command ordering, bounds, rounding and acknowledgement/readback semantics; they cannot establish perfect optical smoothness or eliminate every hardware timing limit.
